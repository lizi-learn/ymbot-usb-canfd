# 电池远程开关验证：1003 与 1008 两次实测

本次整理两次历史试验，验证的是**电池 BMS 放电开关的关闭、状态读回与恢复**。1003、1008 是台架记录标签，电池可拆卸，不能把机器人编号当作永久电池身份；操作前均须重新核对当前电池与固件。

## 两次试验分别得到什么结果

| 记录 | 当次电池 | 放电关闭 | 恢复输出 | 主控自动启动 |
| --- | --- | --- | --- | --- |
| 1003，2026-10-27 | HKMS3.1.T，13 串 / 20Ah | 控制位与 MOS 反馈均关闭 | 延迟读回确认两组均开启 | 另有主板身份、启动状态与服务核验，单次通过 |
| 1008，2026-10-30 | HKMS3.3.J，13 串 / 22Ah | 连续三次读回均关闭 | 一次恢复后读回两组均开启 | **本篇未复核独立主板上线证据** |

两次都只有一次关闭、一次恢复，没有自动重发、电机命令或保护阈值修改。这些结果支持当次 BMS 状态切换，**未用外部仪表确认输出端子电压为 0V，也不是电气安全或反复循环验收**。

## 1003：关闭、蓝牙恢复与主控启动

这次先由主板发出一次关闭请求，再由外部 PC 通过 BLE 独立读取电池。关闭请求后的连接结束没有被当作完成依据；以随后读回的控制位和 MOS 状态交叉确认。

| 时间（Asia/Shanghai，2026-10-27） | 观察 |
| --- | --- |
| 04:46–04:47 | 一次放电关闭请求，无自动重发 |
| 04:55:11 | 外部 BLE 身份核对一致；控制组与 MOS 反馈组均为 `[1,0]` |
| 04:59:01 | 一次恢复请求；即时控制组为 `[1,1]`，MOS 反馈仍为 `[1,0]` |
| 04:59:39 | 再次只读确认：两组均为 `[1,1]`，期间未追加开关写入 |
| 05:00:50 | 独立确认主控网络接口与网页可达 |
| 05:01:14 | 核对主板身份、启动状态及根 / 启动分区可读写；未发现电机驱动运行 |

即时控制值改变不等于 MOS 已切换，因此先等待新的独立读回，而不是因一次读回未更新就重复写入。04:59:39 是确认时间，不能据此认定物理 MOS 的切换耗时为 38 秒。

## 1008：关闭三次读回，随后恢复

关闭前 Linux 已正常关机，所以 SSH 离线不能作为本次电池切断的新证据。试验通过外部 BLE 核对身份和状态，再发送一次关闭请求。

| 时间（Asia/Shanghai，2026-10-30） | 控制组 `[充电,放电]` | MOS 反馈组 `[充电,放电]` |
| --- | --- | --- |
| 关闭前 | `[1,1]` | `[1,1]` |
| 01:16:16，第一次读回 | `[1,0]` | `[1,0]` |
| 01:16:22，第二次读回 | `[1,0]` | `[1,0]` |
| 01:16:33，第三次读回 | `[1,0]` | `[1,0]` |
| 01:25:21，恢复前 | `[1,0]` | `[1,0]` |
| 01:25:23，一次恢复后的读回 | `[1,1]` | `[1,1]` |

关闭试验窗口为 01:16:15–01:16:33，关闭后 BLE 仍可访问。本次恢复记录证明 BMS 报告 MOS 已开启；若要判定主控自动启动，还需另查主板身份、启动时间及服务上线记录，不能仅凭 BLE 写入成功推断。

### 状态字和保护参数有没有改变

- 原有 `0x006F=1` 在关闭、恢复后都保留，没有执行清故障或保护重置。
- 关闭后 `0x0073` 新增 bit9，即 `0x0200`；恢复后该新增位消失。
- 捕获的保护参数 `0x0130–0x016F` 前后比较不变。
- `0x0110` 的动态读数由 50179 变为 50239，未写这个地址。因此不能把结果概括为“整块寄存器全不变”。

## 实际检查的是哪些地址

控制位与状态反馈是两组不同地址。下表解释本次记录的读回含义，不是通用电池控制接口。

| 地址 | 本次用途 |
| --- | --- |
| `0x0121` / `0x0122` | 充电 / 放电控制值；本次单次开关请求使用放电控制 |
| `0x0052` / `0x0053` | BMS 报告的充电 / 放电 MOS 实际状态 |
| `0x006D–0x0073` | 比较关闭、恢复前后的状态字 |

地址定义核对了第三方 [esphome-daly-hkms-bms 固定提交](https://github.com/patagonaa/esphome-daly-hkms-bms/blob/732d8129974fbb4210fec3ff0bdb9bf146859bf6/components/daly_hkms_bms/daly_hkms_bms_registers.h)。这是版本化实现参考，不是厂商对所有 HKMS 固件的控制保证；P81 的这组地址也不能与旧 D2 的 `0xA6` 混用。

## 为什么需要外部蓝牙主机

受控主板可能随放电输出关闭而失去供电，不能依赖它自己继续发送恢复请求。此次使用独立供电的外部 PC 连接仍可访问的电池 BLE，先读回身份与状态，再完成单次恢复。

两次记录没有证明远程互联网开机可靠。要实现该用途，还需要独立供电、位于电池蓝牙可达范围的网关，以及对应的长待机和网络恢复验证。
